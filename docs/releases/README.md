# 发布说明（按版本维护）

每个发布到 GitHub Releases 的版本对应本目录下一个文件，文件名就是版本号（不带 `v`），例如 `1.0.12.md`、`1.0.13-beta.1.md`。

- 首行 `# 副标题` 会成为 release 标题里 `—` 后面的部分：`BfClash <渠道><版本> — 副标题`（Beta/RC 前缀由版本号自动得出）。
- 首行之后的全部内容原样作为 release 正文（Markdown）。
- 文件随该版本的发布提交（`chore(release): …`）一起进入仓库；`android.yml` 的 `publish_candidate` 任务在检出的代码里读取它，**找不到文件就直接失败**，不回退到任何固定文案。
- 只写用户可见的变化，附源码提交与构建记录；不要放订阅链接、节点凭据、令牌等敏感信息。
